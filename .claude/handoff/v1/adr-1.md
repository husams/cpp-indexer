# ADR-1: cpp-mcp boundary — schema prompt lives in cpp-indexer; cpp-mcp consumes it

Status: accepted
Date: 2026-05-17
Resolves: PRD v1.1 Q5 (hard blocker for M6 per CHARTER)

## Context

PRD Q5 asks whether the agent-facing schema prompt (`prompt/graph_database/cpp/schema.txt`) and its companion idiom file (`example.txt`) should live in this repository (cpp-indexer) or in the separate cpp-mcp repository that exposes the graph DB to the CodexGraph Streamlit agent.

Forces:
- The schema is generated from the Rust `NodeKind`/`EdgeKind` enums; the generator must live where those enums live (this repo).
- The drift-detection gate (AC-M6-3, AC-M6-6, AC-M6-7) requires both producer (indexer) and consumer (cpp-mcp) to agree on a `SCHEMA_VERSION` value and the textual content of the prompt.
- cpp-mcp is a runtime consumer; it must not generate or mutate the schema text.
- The Streamlit agent reads `schema.txt` at agent startup; cpp-mcp is the runtime carrier.
- Putting the prompt source-of-truth in cpp-mcp would require cpp-mcp to import a Rust build artifact at release time, inverting the natural producer/consumer arrow.

## Decision

The single source of truth for `schema.txt`, `example.txt`, and `SCHEMA_VERSION` is **cpp-indexer**. Concretely:

1. `prompt/graph_database/cpp/schema.txt` is generated by `build.rs` in this repo from `src/schema/{nodes,edges,version}.rs`. The generated file is committed (CI fails on drift — AC-M6-3).
2. `prompt/graph_database/cpp/example.txt` is hand-authored in this repo and kept under code review here.
3. `SCHEMA_VERSION` is a `const &str` in `src/schema/version.rs`. Every indexed graph writes a `SchemaVersion` node carrying this string (AC-M6-6). Phase 5 refuses cross-repo resolution on mismatch (AC-M6-7).
4. cpp-mcp consumes the prompt by **vendoring the published artifact** from a tagged cpp-indexer release (git submodule OR scripted copy from the release tarball; choice deferred to cpp-mcp's own ADR). cpp-mcp MUST NOT regenerate or edit `schema.txt`.
5. cpp-mcp queries `SchemaVersion` at startup and on every long-lived session; if the live graph's version differs from the vendored `schema.txt`'s embedded version comment, cpp-mcp returns an error to callers (mapped to AC-M6-7) rather than silently answering stale queries.
6. Coordination contract: a tagged cpp-indexer release (semver) is the upgrade unit. cpp-mcp's CI tracks the latest compatible cpp-indexer tag; mismatch is a release-engineering concern handled outside this repo.

## Alternatives considered

- **Schema lives in cpp-mcp**: rejected. Rust enums in this repo are the actual source of truth for what the indexer emits; copying them into cpp-mcp creates two sources of truth and guarantees drift.
- **Schema lives in a third shared repo (e.g., codexgraph-schemas)**: rejected for v1. Adds a third release lifecycle and a third CI pipeline for one file; not worth the overhead at current team size. Revisit if a second indexer (e.g., a Rust indexer for a different language) appears.
- **Schema generated at cpp-mcp runtime by querying the live graph**: rejected. Couples cpp-mcp startup to graph availability and to a healthy `SchemaVersion` node; defeats the drift-detection purpose since cpp-mcp would always "agree" with whatever it found.

## Consequences

Positive:
- Producer (cpp-indexer) owns the canonical artifact; drift impossible at source.
- cpp-mcp release cycle is decoupled from indexer development; cpp-mcp pulls in new schema versions deliberately.
- AC-M6-1..9 all become testable inside this repo's CI without cpp-mcp coordination.
- Schema-prompt regeneration is a `cargo build` side effect, not a manual checklist.

Negative:
- cpp-mcp gains an external dependency on cpp-indexer release tags.
- A schema-only patch in cpp-indexer requires a new release tag for cpp-mcp to consume.

Follow-ups:
- Document the consumption protocol in cpp-mcp's README (out of scope for this repo).
- Add a `cxg-index --print-schema-version` subcommand for ops convenience (deferred; not required for any AC).

Revisit if: a second indexer (non-C++) materialises and shares the schema text — at that point promote to a shared crate.
