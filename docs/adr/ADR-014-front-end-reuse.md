# ADR-014: Front-end reuse remains an explicit, versioned no-ship seam

- Status: accepted
- Date: 2026-07-31
- Scope: S-075 / PERF-002.8
- Consumers: S-076, S-078, T-043, T-050, T-051

## Decision

CIDX does not ship generated umbrella-PCH injection or Clang precompiled-
preamble/`ASTUnit` reuse in this iteration. The selected production mechanism
is `none`, represented by the versioned `front-end-reuse/v1` identity. The
existing LibTooling `IndexSession` and isolated `ClangTool::run` path remain the
semantic control.

The decision is deliberately a no-ship decision, not a port of the retired
Python/libclang cache. The qualification probe exercises three concrete paths:
the normal `SyntaxOnlyAction` control, an umbrella PCH generated by the LLVM
driver and then loaded with `-include-pch`, and an `ASTUnit` construction path.
A future ship decision must replace this ADR with new corpus evidence and
retain the same public identity contract.

## Candidate comparison

| Candidate | Decision | Technical reason |
| --- | --- | --- |
| No reuse | Selected | Preserves current semantics, diagnostics, canonical output, startup, memory, and worker isolation while the identity/handoff seam is published. |
| CIDX-generated umbrella PCH | Rejected for this iteration | A safe prefix and configuration cluster require proof across Clang/resource versions, driver mode, target, ABI flags, sysroot/include roots, macros, generated inputs, and header dependencies. Without a content-addressed, integrity-checked, failure-atomic store, injection would create a dangling `-include-pch` failure mode. |
| Precompiled preamble / `ASTUnit` reuse | Rejected for this iteration | `ASTUnit` ownership and preamble lifetime do not fit the current isolated per-TU `ClangTool::run` action contract or the bounded worker/session boundary without introducing unqualified cross-worker state and memory retention. |

The probe and the existing header-heavy benchmark harness are retained as the
reproduction boundary. The probe retains three trials per path. The generated
PCH path demonstrates candidate-specific setup and load behavior, but all three
loads are rejected by a Clang builtin-module compatibility diagnostic; the
ASTUnit path measures fresh isolated ASTUnit construction and does not retain a
reusable owner. The rejected paths are not presented as shipped acceleration.
The evidence-backed conclusion is that the required failure and compatibility
guarantees are not yet qualified,
so shipping no reuse is safer than claiming a front-end benefit that cannot be
attributed without changing semantics or worker isolation.

## Identity contract

`src/ast/front_end_reuse.*` publishes `front-end-reuse/v1` with:

- mechanism (`none`, `generated-umbrella-pch`, or `precompiled-preamble`);
- driver, working directory, language, language standard, target, ABI flags,
  sysroot, Clang resource directory, include paths, macro state, relevant
  environment, generated inputs, diagnostic policy, and the complete normalized
  invocation argument vector;
- reusable-prefix path, content SHA-256, and dependency SHA-256 values when a
  future non-`none` mechanism is selected;
- canonical JSON bytes and a `sha256:`-prefixed SHA-256 digest.

Ordered invocation and macro inputs remain ordered because their order can
change compiler semantics. Prefix records and dependency digests are sorted
by stable content identity. The deterministic `none` identity is directly
consumable as a field in S-076's TU cache key.

## Failure and operator policy

No generated artifact path exists in the selected branch: no artifact is built,
published, loaded, or injected, so missing/stale/corrupt/version-skewed
generated artifacts fall through to the normal parse before Clang is launched.
`--no-front-end-reuse` is accepted by both the typed and compatibility CLI
parsers and is also exposed by `benchmarks/indexing/production.py`.

Build-declared `-include-pch` arguments are different: they are compilation
semantics and remain in the invocation. CIDX preflights missing/unreadable
declared inputs and returns an explicit diagnostic before Clang; an existing
but incompatible input is passed unchanged so Clang reports the parse error.
It is never silently stripped or converted into a successful no-PCH parse.

When profiling is enabled, the output records
`front_end_reuse.mechanism.none`, zero generated artifacts, and declared-PCH
diagnostic counts. Existing front-end, memory, disk, and worker telemetry stays
the source of measured control evidence; no generated-artifact telemetry is
claimed on the no-ship path.

## Module and ownership boundary

Pure identity and planning live in `extraction.ast` with no filesystem or
process dependency. Build-declared-PCH preflight lives in the existing
foundation utility layer. The benchmark probe lives under `benchmarks/indexing`
outside the production module manifest. Artifact-store and worker-sharing
implementation remain unshipped; S-074 owns worker sharing, lifecycle,
scheduling, and aggregation.
